## 4. 守る開発方針

1. **GitHub `main`をコードの正本**にする。ChatGPTチャットは相談・変更作業・実機テスト結果の報告場所。
2. **開発チャットは「00｜統合開発」の1本に集約する。** 設計・変更作業・実機テスト結果・次タスクの判断はこのチャットで行う。
3. **Development / Debugを維持。** ゲーム完成後にテスト表示・診断機能を整理して製品版に昇格する。現時点ではプロダクトコードの大規模分割は急がない。
4. **固定URL `komorebi3d/dev.html` を開発の入口**にする。テスト前にGitHubへのコミットと公開ページの反映を区別する。
5. **通常保持するゲームHTMLは3種類のみ:** `dev.html`（開発版）＋最新の実機PASS版＋1世代前の実機PASS版。新バージョンのPASS後、旧い2世代前のHTMLは履歴からの復元可能性を確認してから `main` より削除する。現在は v0.7（最新）と v0.6（前世代）。
6. **通常、バックアップ用ブランチは作らない。** Gitのコミット履歴を通常の復元方法とする。履歴改変やリポジトリ消失に備える必要がある重要な節目では、別途バックアップ方法を検討する。
7. **重要資材は保護する。** 実機PASS版やGit履歴など重要資材の削除・履歴改変は、事前に対象を示して個別承認を得る。PASS版の通常の世代ローテーションは決めた保持ルールに従う。
8. 動作確認の報告では、**静的チェック／自動テスト／Safari実機PASSを区別**して記録する。

## 5. ブランチ運用と復元方法

**運用ブランチは `main` のみ。** 共通Engine、開発用 `dev.html`、最新・前世代の実機PASS版を `main` で管理する。

通常は `main` のGit履歴（保持されている範囲）から古い版を復元する。通常保持するゲームHTMLは `dev.html`・最新PASS版・1世代前PASS版のみ。現在のPASS版はv0.7とv0.6。

**注意:** Git履歴は、履歴の書き換えやリポジトリ消失に備える外部バックアップの代わりにはならない。
