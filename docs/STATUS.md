## 4. 守る運用ルール

1. **GitHub `main` がコードの正本。** 通常バックアップ用ブランチは増やさず、変更は小工程でコミットする。
2. **開発入口は `dev.html`。** 固定Engineの参照、安定版v0.7/v0.6、Git履歴・重要資材を無断変更しない。
3. **通常のゲームHTMLは3本:** 開発用 `dev.html` ＋ 最新の実機PASS版 ＋ 前世代の実機PASS版。追加のアーカイブHTMLは置かない。旧世代の削除には復元可能性の確認が必要。
4. **検証結果を混同しない:** 構文/静的テスト、模擬テスト、Safari実機PASS、未検証項目をそれぞれ明示する。
5. **GitHub Pagesの反映に注意:** GitHubでコミット済みでも公開ページやSafariキャッシュの反映は別。画面の「GitHub main最新コミット」表示はページ自身の配信版SHAを証明しない。
6. **開発は「00｜統合開発」で一元管理。** 実機PASS後・方針変更後・チャット移行前にはこのSTATUSを更新する。

### 00｜統合開発での質問フォーム運用

- **質問の基本形:** `Q〇〇. 質問内容` → **ラジオボタンで選ぶ回答候補** → **コメント欄（任意）**。各設問に個別のラジオ選択と任意コメントを用意する。
- **複数質問の一括回答:** 確認したいことが複数ある場合、Q番号を付けて**1つの回答フォームにまとめる**。最後に**送信ボタンを1つ**置き、全設問の選択結果とコメントを**1回の送信で、Q番号付きでチャットへ返せる**ようにする。
- **使いやすさ:** コメントは空欄でも送信可能。必要な質問だけをまとめ、関係のない確認や過剰な設問を増やさない。単独の質問でも同じ基本形を使える。チャット内で操作できるラジオ等を優先する。
- **Q番号のリセット:** 「00｜統合開発」チャットを新しく作り直したときは、質問番号を **Q1から開始してよい**。前のチャットで使った最後のQ番号を引き継ぐ必要はない。同じチャット内では番号を順番に付ける。
