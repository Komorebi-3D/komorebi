# 🌳 GitHub・開発・検証の運用ルール

## 1. 正本と変更時の許可

1. **GitHub `komorebi-3d/komorebi` の `main` がコードの正本。** コードの閲覧・検証はよいが、**ファイルの作成・更新・削除・コミットなどGitHubへの書き込みはユーザーの明示的な許可を得てから**行う。
2. 通常のバックアップ用ブランチを増やさず、変更は小工程でコミットする。検証用の一時ブランチを用いる場合も、長期保存するバックアップと混同しない。
3. **開発入口は `komorebi3d/dev.html`。** 固定Engineの参照、Git履歴、重要資材を無断で変更しない。現時点の変更禁止対象・最新の開発状況は [STATUS.md](../STATUS.md) に記す。
4. **v0.7・v0.6の実機PASS済み安定版は保護する。** 正式な世代交代など、ユーザーが内容を確認した場合を除き、編集・削除しない。
5. 通常のゲームHTMLは開発版 `dev.html`、最新実機PASS版、前世代実機PASS版の3本。`mock.html` は軽量な**UI検証用ページ**であり、安定版・保存用アーカイブではない。不要なバックアップHTMLを増やさない。

## 2. 検証結果は混同しない

- **静的チェック／構文チェック／ビルド生成物の一致／模擬ブラウザ試験／GitHub Pages公開版の確認／iPhone・iPad Safari実機PASS**は、対象と確認内容を分けて記録する。
- 未報告の端末別確認、A/B描画、全24配置の網羅検証などを推測でPASSにしない。
- GitHubへのコミット完了と、GitHub Pagesの配信更新・Safariキャッシュ更新は別。表示される「最新コミット」だけで配信ページ自身のSHAが証明されたとは扱わない。

## 3. 作業の継続と記録

- 開発と引き継ぎは原則「00｜統合開発」で一元管理する。
- 実機PASS後・方針変更後・チャット移行前には、[STATUS.md](../STATUS.md) の**現在地・未完了タスク**を更新する。完了済み工程の長い時系列は積み増さない。
- **安定的な運用ルールは `docs/rules/` に置く。** `STATUS.md` の定期更新にルール変更を紛れ込ませず、ルール変更時は別途ユーザーと合意する。
- 新しいチャットでは [ルール目次](README.md) と [STATUS.md](../STATUS.md) を読み、必要なGitHub最新ソースを確認して、ユーザーが現在希望する工程から始める。

## 4. 開発情報パネルの更新（緩やかな運用）

- 開発情報の保存先は `komorebi3d/development-info.json`。キーは `engine`（固定Engine SHA）と `forest` / `matsudo` / `common`（それぞれ最新の短い1文）。
- コード変更に合わせて、**該当する区分だけ**情報ファイルを更新する。変更していない区分は保持する。初期値・未登録値は「更新履歴なし」。
- コミットメッセージは更新後の情報ファイルを元に、`forest: ...` / `matsudo: ...` / `common: ...` を行頭に付ける。複数区分を変更した場合は、コミット本文に区分ごとの行を記載してよい。
- 画面の 🆕 は **GitHub main最新コミット**のメッセージにある区分だけに付ける。保存済みの説明が「更新履歴なし」の場合は付けない。GitHub APIが取得できなければ 🆕 は付けず、説明は保存済み情報を表示する。
- 開発情報パネルはページ表示・再読み込み時に取得し、開いたままの定期更新はしない。コミットSHA・日時はGitHub APIから取得し、JSONに複製しない。
- **強制チェック・コミット阻止・専用スクリプトは設けない。** 更新漏れに気づいたら、その時点で修正する。今までのPASS版や固定Engineには手を加えない。
