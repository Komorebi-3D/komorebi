# 🌳 チャット内モックの生成・表示ルール

## 1. パネル数・種類・配置を独立して扱う

チャット内モックは、依頼に応じて**1～4パネル**を表示する。パネルの**数・種類・配置位置**はそれぞれ独立した条件であり、「2パネルなら上＋左」のような固定の組み合わせを前提にしない。

| 指定事項 | 選択肢 |
| --- | --- |
| パネル数 | 1、2、3、4 |
| パネルの種類 | `build`＝🧪開発情報、`game`＝🎮ゲーム画面、`test`＝🧪テスト操作、`runtime`＝📊実行ステータス |
| 配置スロット | `top`＝↑上、`left`＝←左、`right`＝→右、`bottom`＝↓下 |

- **ユーザーが指定したパネルとスロットだけを初期配置**する。不要なパネルを人数合わせで追加しない。同じパネル種類を複製したり、2種類を同一スロットに重ねたりしない。
- 数・種類・位置の一部が省略されている場合は、**直近で確定した構成を引き継ぐ**。新しいチャットなどで、その履歴が確認できず構成を特定できなければ、必要な不足条件を確認する。勝手に標準配置を決めない。
- 1パネルの場合も要求されたスロットへ配置する。空きスロットの表示・追加メニューは、**モックに実際に存在するパネル・スロット**の範囲で扱う。
- 「1～4パネルで表示できるようにする」という**チャット内モックの作成方針**と、実際に作成・検証済みのモックやビルド機能の対応範囲を混同しない。

## 2. GitHub `main` の軽量モックソースを出発点にする

- **まずGitHub `main` の最新のモック専用ソースを読む。** 本番 `dev.html`、`dev.template.html`、`panels/game.html`、`panels/game.css` のゲーム本体を複製して、チャット内モックを作り直さない。
- 現在あるモック用ソースは次のとおり。**これらは現在の2パネル構成向け**なので、1・3・4パネルへの自動対応を意味しない。
  - `komorebi3d/mock.template.html`：2パネル用の外枠・配置・起動
  - `komorebi3d/mock-layout.css`：モック専用のレスポンシブ配置
  - `komorebi3d/panels/game.mock.html`・`game.mock.css`：黒いゲーム仮画面とⓘ
  - `komorebi3d/panels/build.html`・`build.css`：開発情報パネル
  - `komorebi3d/common.css`：共通スタイル
  - `komorebi3d/dev-panel-layout.js`：共通のパネル操作ロジック
- `test` や `runtime` が要求された場合は、最新ソースと要件を確認し、**軽量なモック用部品がなければ必要最低限を用意**する。本番ゲームのEngine、WebGL描画、ゲーム入力、未指定のパネル専用処理を無断で含めない。操作の模擬が必要なら、本物のGame APIと区別できるモックを用いる。
- 元のCSS・共有JSは必要箇所だけを利用する。不要な本番コードを取り込まず、既存の共通仕様を勝手に改変しない。

## 3. チャット内表示の進め方

1. パネル数・種類・位置と今回の確認目的を、ユーザーの指定と直近の確定内容から特定する。
2. 軽量ソースを基準に、**チャット内で操作可能なプレビュー**として再現する。外部モジュールを直接読み込めない環境では必要部分のみを同等の挙動にし、本番Engineへ差し替えない。
3. 必要な場合はⓘ押下中の説明・ゴミ箱同時表示、ドラッグ交換・削除、空き枠の＋からの再追加、**スロットの高さ保持**を共有仕様に従って維持する。画面幅が狭い場合は無理にiPad幅を強制せず、レスポンシブの意図を保つ。
4. **大きなモックを表示する前に、出力予定コードの行数・文字数を実測し、別の返答で事前報告する。ユーザーのOKを待ち、了承を得た次の返答で初めてモックを表示する。** 推定値を実測と称しない。
5. モック表示の依頼だけではGitHubを変更・コミットしない。チャット内モックのPASS、ビルド生成のPASS、公開版・Safari実機PASSを分けて記録する。

## 4. ビルド引数とチャット内モックを区別する

- 現在の `node komorebi3d/build-dev.mjs --mode=mock` は、**既存の2パネル（上＝build、左＝game）**を `komorebi3d/mock.html` に生成する。引数だけで任意の1～4パネル構成を生成する機能ではない。
- `node komorebi3d/build-dev.mjs --mode=product` と引数なしは、既存の4パネル本番開発ページ `komorebi3d/dev.html` を生成する。
- `--check` はソースと生成HTMLの一致検証。チャット内モックを表示するだけなら、ビルドコマンドやGitHubコミットは不要。
- ビルド側を別のパネル数・配置に対応させる変更は、**ユーザーが指示した場合に別工程として設計・検証**する。チャットの「モック出して」をその変更の許可と解釈しない。
